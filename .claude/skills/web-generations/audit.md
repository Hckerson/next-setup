# Audit

Run after building, or on request to review existing UI. Grade each layer touched; never grade a project as a whole.

## 0. Scope before searching

1. **Read `.claude/CLAUDE.md` and `eslint.config.ts`.** A tell already banned by a lint rule is reported as a lint finding, not as a generation finding. Do not restate enforced rules. If the code has no `eslint.config.ts` (a scratch build), apply the `CLAUDE.md` rules directly and say so.
2. **Map layers to files** with `docs/UI_LAYERS.md`. `components/features` holds marks, rows, lists and modals together; select by what a component renders, using file names only as a hint (`*-mark.tsx`, `*-status*`, `*-row.tsx`, `*-list.tsx`, `*-modal.tsx`). A domain mark named otherwise (a routing strip, a stamp, a progress glyph) is still a mark; a skeleton is Pattern wherever it lives. `components/sections` holds sections and consoles (`*-console.tsx`). A layer is graded only on its own files.
3. **Include where the look really lives**: `*.module.css`, `styles/`, and the config a primitive imports (`lib/config/`, motion and floating constants). For chrome and root, include `app/layout.tsx` and the portal layouts: skip link, route focus and the main landmark live there.
4. **Name the surface**: app or marketing. A criterion tagged for the other variant is not graded.
5. **Read `docs/DESIGN_BRIEF.md`.** Grade decisions against it: a layer that contradicts the brief (a different accent, density or status vocabulary) is a finding. A layer that matches the brief but reads as a reference product's look fails `differentiation.md`. Without a brief, say so in the report: the project's own decisions are unrecorded.

Dead-token procedure. A token is **live** when it is referenced anywhere: as `var(--token)`, or through Tailwind v4's shorthand `prop-(--token)` (for example `h-(--sizes-row)`, `duration-(--durations-exit)`), including inside the token file (generator inputs such as hues and lightness steps are consumed only there, and that is live). A theme alias (`--color-x: var(--colors-x)` in an `@theme` block) counts only if the utility it creates (`text-x`, `bg-x`) is used; `--font-sans` and `--font-mono` are consumed by Tailwind's preflight (`--font-mono` only when `code`, `kbd` or `pre` exist). A token is **dead** only when none of these applies.

```
for t in $(grep -oh '^\s*--[a-z0-9-]*:' styles/tokens.css | tr -d ' :' | sort -u); do total=$(grep -rE -- "(var\($t\)|\($t\))" styles app components lib 2>/dev/null | grep -v "^[^:]*:\s*$t:" | wc -l); [ "$total" -eq 0 ] && echo "$t"; done
```

Then, for each name it prints, check whether it is only an alias target by searching the utility name. Use `grep -r` where `rg` is not installed, and skip any folder that does not exist.

Report unused tokens and classes; do not delete them. Project rule: unbuilt is not dead; say so and wait.

## 2. Run the five discriminating checks

These separate fourth from fifth when behaviour already passes. See `generations.md`.

1. **Elevation**: is depth one recipe chosen for the register (ladder and hairlines, tone steps, a hard lip, solid rules, fills, or none) and applied consistently, rather than one soft shadow repeated on every card? On a light theme a faint, tight edge shadow at a few percent alpha is allowed on resting surfaces; the tell is uniformity and a shadow change as the hover affordance. `[source]`
2. **Radius**: is the radius a decision recorded in the brief (a family, or one deliberate value) rather than a library default, and are radii named tokens rather than a calc off one value or the spacing base? Where an inner edge sits close to an outer one, is the inner radius the smaller? List the distinct radius classes per layer. `[source]`, nesting partly `[app]`
3. **Transitions**: does each name its property and take a duration and easing from a token? A literal that equals a token's value still fails. `[source]`
4. **Overlays**: does every overlay have a designed enter and exit, or a recorded instant cut, as the brief states? Whether the exit is faster, equal or slower is the register's call recorded in the brief; nothing should pop by omission. `[source]` for existence, `[app]` for feel
5. **Tokens**: is every token live, and does every look value come from one? `[source]`

## 3. Grade each layer

Walk the layer file's Checks. Assign the generation the layer reads as, by **prevalence**, not by the single worst hit:

- **Recurring**: the same tell in 3 or more files, or in a shared primitive, class or token that many files consume. A recurring tell sets the layer's grade.
- **Isolated**: 1 or 2 files. List it with its IDs and fix it, but it does not lower the grade by itself.

The grade is the lowest generation reached by a recurring tell. A layer with only isolated hits and every Baseline criterion met is graded **Fifth**, with the isolated hits listed.

A layer with no recurring tell but one or more Baseline criteria unmet is graded **Fifth with gaps**, and the unmet criteria are listed by name. It is not Fifth until they are met or named as deliberate exceptions. A layer with only part of its files built is graded on the parts that exist, and the report says which parts are missing; a layer with no files is **Not built**, never "not found" and never graded.

**One selected-state recipe.** Hover, focus-visible and selected each have one recipe that is reused on every surface of its kind (rows, nav items, tiles). Which recipe is the register's call (a wash ladder, a border plus fill, an ink pill); a different improvised mechanism per component is the gap.

**Register fit.** After the baseline, check the layer against the register the brief names: does it realise the layer the way `registers/<name>.md` describes, or the way a different register would (most often developer-tool by default)? A layer that meets the baseline in the wrong register is **Fifth, off-register**: not a quality failure, a brief violation. Without a brief, register fit is not graded; say so.

A single-consumer role or material class is an isolated finding, never a recurring one.

**Thin criteria are advisory.** A Baseline criterion tagged `(J)`, or `(S n/18)` with n of 2 or less, or labelled "Thin", is reported when unmet but does not by itself lower a layer from Fifth to Fifth with gaps. List it under the table as a recommendation.

**Applicability.** A criterion whose subject does not exist in the build is N/A, not unmet: no destructive action means no danger tone is required; a list with one facet needs no filters; an app with no display role compares title with body. Say N/A and why.

**Off-token findings and shared primitives.** An off-token literal (an icon size, a stroke width, an arbitrary value) inside a shared primitive counts as recurring through every consumer of that primitive. A recurring off-token finding sets **Fifth with gaps**, never Fourth on its own (it is a token gap, not a default cluster); an isolated one is listed only. Check every shared primitive for them, not only the first one found.

**Drift signals** from the detector table are graded under register fit, not under the generation: they show where the build slid toward a default or toward the developer-tool family against its brief.

Checks tagged `[app]` need a running app: rendered colour and contrast, motion feel, hover and focus order, alignment, "dimmer" and composition. When the user asks to verify, run them with `verify.md`; otherwise they go to **Unverified**, never to pass or fail. Checks tagged `[source]` or untagged can be answered from the code.

Evidence is a file and line, or a screenshot region, with the count of sites. A grade without evidence is not a grade.

**Trace to the root.** Each layer file names its upstream layers, following `docs/UI_LAYERS.md`: each layer is built from the ones before it. A recurring tell is usually inherited: a repeated shadow tile across many sections is a missing shared treatment in Pattern or Token, not many section bugs. Name the layer where the tell originates, fix it there, and re-grade the layers below it. Never fix 14 copies and leave the cause.

## 4. Fix or justify

- **Third or older**: fix with the tell's replacement.
- **Off-register**: realign to the brief's register, or change the brief if the register was wrong; never both silently.
- **Fourth**: fix, or record a reason from the dial in `SKILL.md`. Name the missing property from the layer's Baseline. An audit never invents the reason: if none is given, write `reason: pending (user)`.
- **Deliberate exception**: record the device, the reason and where it is confined. The audit may propose candidates; it does not assume them.

## 5. Report

One table, then the lists.

```
| Layer | Generation | Register fit | Prevalence | Tells hit (IDs) | Unmet Baseline criteria | Evidence | Action or reason |
```

Then, in order: **Isolated hits**, **Deliberate exceptions** (and candidates for the owner to name), **Not audited**, **Unverified** (everything tagged `[app]`).

## Calibration

`references/ground-truth.md` records what two real frontends read as. Using it is optional for a normal audit and required when changing a layer file. The test: run this audit blind on the same layers and confirm it finds the same fourth-generation tells and does not flag the fifth-generation craft the file lists. If it cannot tell them apart, the layer files are too vague; report that instead of grading.

A blind **build** test on 2026-11-09 had an agent build six layers of a manufacturing work-order list using only the skill, and a second agent audit it blind. The build met nearly every criterion and still failed `differentiation.md`: it was Linear's issue list with new words, because the layer files then named Linear's shapes, weights and row order. That is why `(S)` criteria now state properties and leave instances to the brief.

A three-register build test on 2026-11-11 (industrial, warm utility, playful; one work-order list each, audited blind) met the baseline in every built layer and differed by 7 to 8 axes between builds, but two builds cloned an exemplar of their own register (playful matched Duolingo, warm matched Notion, on 7 axes). The cause was register files that stated one exemplar's instances as the register's positions, and a brief written to those positions. The gate now compares instances on free axes, and the brief commits to its differences before building. A rerun the same day, with each builder writing its own brief through the skill from domain facts only, passed: every built layer Fifth or Fifth with gaps, builds 6 to 8 axes apart, and no build above 2 of 5 free axes against any exemplar (playful went from 7 matches with Duolingo to 0).

A blind run on 2026-11-09 against real-estate did this: it found the repeated shadow tile (14 files), card lift, `transition-all` (10 files), literal durations (164 against 2 token uses) and dead tokens, and credited the command palette, `aria-current` and modal motion. It also found a hard-coded `aria-expanded`, no focus trap on a hand-rolled drawer and no skip link, which the first calibration had missed.
