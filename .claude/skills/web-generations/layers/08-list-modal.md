# Layer 8: List and modal

`components/features/`. An entity list with its filters and states, and the modals, drawers and menus that act on it.

**Upstream:** Token, Primitive, Pattern, Mark, Row. A recurring tell here is usually inherited from these layers: trace it there and fix it once, not once per file here.

## Tells

A tell fires on a list or overlay left at the library's default, decided by nobody. The same choice made on purpose and recorded in the brief (equal enter and exit, an instant cut, a result count with a pager) is a register, not a tell.

## Floor versus baseline

A competent fourth-generation list works and looks finished: a search box, a filter dropdown, a table, a pager, and the library dialog for every confirm and edit. It lacks the empty, loading, error and in-between states designed with the same care as the populated one, filter state that survives a reload, an overlay chosen by how blocking the task is, and enter and exit motion decided rather than inherited.

## Baseline

Every register meets these. Counts are of the 18 exemplars (`references/classification-ledger.md`, section 08).

- **LST-B1. Visible filter state.** Active filters show as state (chips or tabs) and survive a reload and a shared link. Where applicable: only when the list has more than one facet worth filtering; a list with no filters is N/A, not unmet. `(S 4/18)` Stripe, Vercel and Mercury chips; The Pudding's filter tabs. Filter state in the URL was not measured in any exemplar (thin).
- **LST-B2. Overlay by how blocking the task is.** Inline or a side panel for non-blocking work; a modal only for a short, blocking decision. `(S 4/18)` Stripe's ContextView and FocusView, Linear's inline create, Mercury's floating drawer, Notion's side panel.
- **LST-B3. Blocking confirms are modal.** A blocking confirm is a modal that dims the whole page, not a drawer or a non-modal sheet. On narrow touch screens it becomes a modal sheet or a full-screen surface. `(S 1/18)` Vercel. Thin evidence; none breaks it. The sheet on touch is shown by Vercel, Things iOS and Apple Store iOS (ledger 03.8c).
- **LST-B4. Destructive confirmation.** The title is verb plus noun in the brief's casing; the body states the consequence first and whether it can be undone; the destructive button repeats the verb and noun, never "Confirm" or "OK"; initial focus is on the safe action and Enter never fires the destructive one; a high-stakes action asks for one deliberate extra step; button order follows the platform convention; when the object itself is being cancelled, the dismiss action names what is kept ("Keep subscription"). `(S 2/18)` Vercel; Figma's red-outline destructive button. Thin evidence; none breaks it.
- **LST-B5. Designed enter and exit.** Every overlay's enter and exit are designed and recorded in the brief; nothing pops by omission. An instant cut is allowed only as a recorded decision. The exit never delays the user's next action, scrims fade with their layer, and under reduced motion the duration stays above zero where code waits on the transition (TOK-B15). `(S)` Ledger C1. Mercury's app overlays appear in .2s and leave in .15s; Notion enters in .15s and leaves in .2s; Linear's highlight enters instantly and fades out in .15s. Tempo (exit faster, equal or slower) is a recorded brief decision in every register (PRI-B14); no register requires a direction, and equal durations are not a gap.
- **LST-B6. Overlays follow their keyboard pattern.** A modal overlay (dialog, drawer, sheet, a hand-rolled mobile sidebar) traps focus while open, closes on Escape and returns focus to its trigger. A menu or listbox does not trap: focus moves into it, arrow keys move within it, Escape and Tab close it, and focus returns to the trigger. `(S 1/18)` Only Vercel's modal is documented; this is the WAI-ARIA dialog pattern, independent of style. Thin evidence; none breaks it.
- **LST-B7. Menus mark the current item.** A menu marks the current item and shows a shortcut wherever one exists. `(S 3/18)` Linear, Raycast's action panel, Mercury's Command item. Products without shortcuts show none (TE, Nothing, Ableton, Duolingo, Wise app).
- **LST-B8. Focus in menus and lists.** Menu and list items carry a designed focus indicator that is distinct from hover, reaches 3:1 against every adjacent colour, sits inset so it neither clips nor shifts layout, and works without JavaScript; on touch each item is at least 44px tall. `(S 3/18)` Ledger C2 and C6. Mercury menu items inset at -2px, Wise list items at -1px, Linear inner items at a negative offset. The focus indicator differs from any resting border in colour, width or offset, so it is never drawn exactly over the border it sits on.
- **LST-B9. Scrim in the system's temperature.** The scrim is drawn from the ink in the system's one neutral temperature (TOK-B6), not a default black chosen by nobody. `(S 2/18, thin)` Mercury's tinted `#70739338`, Aesop's graphite at 50 percent.
- **LST-B10. Named overlay layers.** Overlays stack in named layers; a toast renders above a modal and stays interactive. `(S 2/18)` Vercel; TE's named z-index tokens. Thin evidence.
- **LST-B11. Designed states.** Skeletons match row geometry and count, an error offers retry, and a partial failure stays in its region. `(S 2/18)` Aesop's and Apple's geometry-matched placeholders; Vercel's isolated error with retry. Thin evidence; none breaks it.

## Techniques

Register-neutral methods, recommended, not required.

- **Use the dialog and menu primitives.** A drawer or sheet built on the dialog primitive inherits focus trap, Escape and focus return; a menu or listbox built on the menu primitive inherits arrow-key movement, Escape and Tab to close, and focus return, with no trap (LST-B6). Rebuilding them by hand is where they break.
- **Per-row mutation state.** Each row owns its pending and error state (a mutation per row, or mutation state keyed by the row's id). Never one shared mutation for every row: a second action must not erase the first row's pending or error state. See LST-B11.
- **Undo before confirm.** Where an action is reversible, an undo toast after the action costs the user less than a confirm before it.
- **Origin for anchored overlays.** If an anchored popover or menu moves on enter, set its transform origin to the trigger's edge so it reads as coming from what opened it. A plain fade needs no origin.

## Token roles this layer needs

Overlay scrim drawn from the ink, overlay enter and exit durations and easings with reduced-motion variants, menu and modal materials, chip states, group header, keyboard-hint type role, named overlay layers (toast above modal), undo-toast timing.
