# Layer 9: Section

`components/sections/`. A band of a page: a hero, a feature band, a proof band, a rail, a pricing block, a dashboard region.

**Upstream:** Token, Brand, Pattern, Mark, Row, List and modal. A recurring tell here is usually inherited from these layers: trace it there and fix it once, not once per file here.

## Tells

A tell fires on a band left at the template's default, decided by nobody. The same device chosen on purpose and recorded in the brief (a tone change per band, one radius across tiles, a scrim on owned photography) is a register, not a tell.

## Floor versus baseline

A competent fourth-generation section is clear, readable and well spaced, and every band has the same composition: a centred title over a grid of equal cards, on a background that alternates. It lacks scale tension between and inside bands, a composition chosen per band, evidence in place of claims, and an order that follows the product's argument. On the app surface it lacks regions sized by the operator's question.

## Baseline

Every register meets these. Counts are of the 18 exemplars (`references/classification-ledger.md`, section 09).

- **SEC-B1. Width and grid.** Marketing: content width is a token and bands share one column grid. The column counts and the width value are the register's. `(S 10/18)` for width tokens (Stripe 1264px, Apple 1260px, Aesop 1200px, Wise 1440px, Press 1280px, Things 900px, and others; TE scales one 980-wide design); `(S 4/18)` for column grids (Stripe 12, 8, 4; Mercury 12; Figma 4 to 48; Nothing 2 to 10).
- **SEC-B2. One headline per band.** Marketing: each band carries one headline. `(S 2/18)` Apple, Aesop. Thin evidence; none breaks it. Apple's two links under the headline are its instance.
- **SEC-B3. A composition per band.** Marketing: header composition varies between bands (split title and lead, header beside media, a quote), and one feature is given scale instead of equal columns. `(S 2/18)` Apple's stacked tiles, each its own composition; Duolingo's tabs sized by purpose. Thin evidence.
- **SEC-B4. Type with tension.** Marketing: display and body differ on at least two axes (size, family or cut, weight, tracking, leading). `(S)` Ledger C4: every premium exemplar passes, including those under 3x, such as Aesop (size, family, leading), Things (size, weight, leading), Duolingo (size, family) and TE (size, optical cut). A 3x size jump is a register position, and any multiplier names its viewport: Apple's 4.7 to 5.6x at desktop is 2.4 to 2.8x at 390px.
- **SEC-B5. Proof is evidence.** Marketing: claims carry evidence (a figure, a named outcome, a disclosure) in the same typographic system as the claim, linked to its source. `(S 4/18)` Wise's rate, fees and savings in the hero; Mercury's footnoted claims; Press's Praise and Reviews; Nothing's delivery, returns and warranty row. Logo rows were not measured.
- **SEC-B6. Themes survive the swap.** Marketing: when a section swaps theme, every role survives the swap and the chrome follows. `(S 4/18)` Mercury's 12 theme classes with the nav re-theming, Wise's themed sections, Apple's `.theme-dark`, Figma's colour pairs per section.
- **SEC-B7. Legible on every band.** Essential text reaches 4.5:1 (3:1 for large text) on every background a band can put behind it: its tone, its theme, and any photograph, with a localised scrim where needed. `(S)` Ledger C3. Apple's grey running copy at 3.62:1 is a defect; the same device passes at #6e6e73 (5.07:1).
- **SEC-B8. Regions follow the question.** App: dashboard regions follow the operator's question, and the most-used region gets the most area. A grid of equal cards is correct when the data is a set of equal items. `(S 2/18)` Stripe overview, Vercel overview. Thin evidence.
- **SEC-B9. A region leads with its task.** App: a title row with its actions, then the figures that answer the question, then the detail beneath. `(J)` Thin: not measured; none breaks it.
- **SEC-B10. One shared emphasis tile.** App: a tile that recurs across regions is one component or one named class, never a class string copied into each file; a copy in three or more files is a recurring tell. `(J, thin)` Project rule (single source of truth); not observable in shipped output.
- **SEC-B11. Emphasis is one recorded device.** Emphasis (a featured plan, a hero tile) is one recorded device, such as luminance, hairline, scale, colour block or fill, and never a generic shadow tile. `(S)` Linear's alpha inset rings, Notion's shadow ladder, Duolingo's lip, Ableton's colour blocks, Figma's maximal colour schemes.
- **SEC-B12. The container is a decision.** Each section's container is a recorded decision: open, ruled, filled or carded. `(S 4/18)` Duolingo's whitespace, Things' surface step, Aesop's open canvas, TE's image tiles with no card chrome. The preference order is the register's.
- **SEC-B13. The hero does not wait.** A hero that is the page's largest above-the-fold element plays without waiting for scroll. `(S 1/18)` Stripe Press. Thin evidence; none breaks it.
- **SEC-B14. The signature has a fallback.** The signature device has a designed fallback for when it cannot run (no WebGL, no backdrop blur, reduced motion). `(S 2/18)` Press's `--isNotWebGL`; Apple's glass nav falling back to a near-opaque fill with no blur. Thin evidence.

## Techniques

Register-neutral methods, recommended, not required.

- **Section padding as a token.** One padding token for bands, with named exceptions for the bands that need more air (Apple's 160px with a 216px variant), keeps the rhythm deliberate. One exemplar, so a technique.

## Token roles this layer needs

Content width, column count by breakpoint, gutter, section padding with named exceptions, display type role, section theme classes that redefine every role, container treatments (open, ruled, filled, carded), the emphasis device, scrim for text over imagery.
