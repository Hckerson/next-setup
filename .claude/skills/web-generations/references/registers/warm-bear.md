# Registers research: WARM UTILITY, third exemplar (Bear)

Method. Shipped stylesheets and bundles were downloaded with curl and read for custom properties and declared values. For Bear this includes the **in-product** web app, so the numbers are app numbers, not marketing numbers:

- Marketing: https://bear.app/ and `https://bear.app/screen.12d14f2b7753c02df6acfd58657a4d480d2c47db80f4aa6d62bf3746d473a25f.css` (2,612 lines).
- Product: Bear Web v0.41.2 (public beta since July 2025, https://blog.bear.app/2025/07/bear-web-public-beta-you-are-invited/): `https://web.bear.app/v0.41.2/css/screen.css` (112 KB, app chrome), `https://web.bear.app/v0.41.2/css/view.css` (29 KB, the Markdown editor), and `https://web.bear.app/v0.41.2/js/app.js`, which embeds the default light theme "Red Graphite" as a JSON theme file (`JSON.parse('{"base":{...}}')`) and sets the defaults `light-theme: "Red Graphite"`, `dark-theme: "Dark Graphite"`. The `view.css` comments refer to "native Bear" and `NSParagraphStyle`, so the web editor renders the native theme template.
- In-product iOS screens from Mobbin (ids below).
- Craft was measured as the comparison candidate (see Choice).

Contrast ratios and OKLCH values were computed by me (WCAG relative luminance; OKLCH from sRGB). Alpha colours were flattened onto their real surface. Tags: Q = QUALITY (register-independent), R = REGISTER choice. Anything not measured is marked UNVERIFIED.

Caveats:

- The Mac and iOS apps are native. Bear Web is the measurable proxy. Its theme JSON is the same format as the native theme (`$base.x` aliases, `modular scale`, `line height multiplier`), but native px sizes may differ. UNVERIFIED for native.
- Only the default light theme is embedded in the bundle. "Dark Graphite" colour values were not found in any shipped file. UNVERIFIED.
- The note-list cell height is computed in JS (`--preview-cell-height` is set from a function in `app.js`), so the row pitch in px is UNVERIFIED.

### Layer notes

- 01 Token: two layers, a theme file of 97 roles (49 of them `$base.x` aliases) over 11 base colours, and a `color-mix` layer that derives every wash, divider and floating border from the text and background colours. Shadow opacities are tokens by size and are re-valued per theme. This is the strongest quality idea here: neutrals form one system by derivation, so any theme, warm or cool, stays coherent.
- 02 Scale class: header sizes come from a modular ratio (1.125) on a 15px body, and the hairline width scales with text size. The chrome has no spacing or radius scale (em values chosen per component). That is a gap, not a register position.
- 03 Primitive: hover is a 15% text-colour wash, not an accent wash. Primary actions on iOS are accent fills (FAB, delete) or accent text on a pale accent wash (Cancel). Fields are about 30px with a `.4em` radius.
- 06 Mark: TagCons (icons per tag) and the pin glyph are marks the user assigns. Highlighter tints are user marks with paired dark text.
- 07 Row: a note row is a preview cell, not a one-line row: a Headline-cut title, 1 to 3 preview lines chosen by the user, an attachment strip, a meta line and a rule. Selection is a neutral fill plus an accent ribbon when the list has focus.
- 08 List and modal: floating panels share one recipe (a text-colour border at 8% or 40%, contact plus ambient shadow, radius 6 to 20 by size). Modal backdrops dim to .35 with a 4px blur. Quick open is a 640px palette near the top.
- 11 Page (editor): a 720px measure inside fluid margins, the red caret, red bullets, quote bars that alternate filled and hollow, visible Markdown markers in tertiary grey, inline tag pills (`#E4E5E6` with `#444` text, 7.72:1).
- 12 Chrome: a charcoal sidebar in a light theme, louder than content in luminance; a 25% list column; floating glass format islands; on iOS, a drawer and a FAB.
- 14 Root layout: light and dark are separate theme files (Red Graphite and Dark Graphite). The `.dark-theme` class re-values shadows and dim. Dark Graphite colours are UNVERIFIED.

### Bear: QUALITY (expect in other registers)

1. Theme as data: a small base palette, component roles aliased onto it, one swap re-skins everything.
2. Neutrals derived by `color-mix` from text and background, so hover, dividers and floating borders stay in one system across themes.
3. Elevation alpha and overlay dim re-valued per theme (light .12 and .35; dark up to .20 and .46).
4. A global reduced-motion block in the app.
5. Selection that shows which column has focus (accent ribbon or neutral; active or inactive text selection).
6. An explicit measure token (48em) and a hairline that scales with text size.
7. Exit faster than enter on floating chrome (.4s spring in, .25s accelerate out).
8. Designed loading, empty and error states (skeleton, placeholder label, empty backlinks, shake, error badge).
9. Highlight tints paired with same-hue dark text at 12:1 or more; tabular numerals on ordered lists.

### Bear: REGISTER

Pure greys with a charcoal sidebar; one red spent as ink inside the text; a geometric house face in UI and Headline cuts; a 1.125 modular header scale on a 15px body; three columns, list and detail; hashtags as navigation with TagCons; Markdown markers left visible; glass format islands; a 2px lip on the FAB; one shadow on marketing.

New example positions the register file can list (directions, each traceable to Bear):

- Accent: a warm non-blue hue spent as the pen's ink inside the content (caret, markers, rules), not on panels.
- Type voice: one geometric house face in two optical cuts (UI and Headline), hierarchy from the cut and a small modular scale, no serif.
- Signature: the user's own markup (tags, markers) made into navigation and ornament.
- Chrome: a dark sidebar inside a light theme, with three columns for list and detail work.

## Quality gaps in Bear (do not copy)

- Secondary text `#888` is 3.54:1 on white and 3.24:1 on `#F3F5F7`. It is used for previews, subtitles and the quick-open hint.
- The note date is `#888` at opacity .7: 2.28:1.
- Accent `#DD4C4F` is 4.02:1 on white for links and list markers. White on the accent (sidebar selected label at 13.9px, marketing button) is also 4.02:1. Both are under 4.5.
- Focus: no `:focus-visible` style in the app chrome; outlines removed 9 times in the app and twice in marketing; the input ring at accent 43% is 1.79:1, under 3:1.
- Marketing: no `prefers-reduced-motion`, no dark scheme, `scroll-behavior: smooth` never reset.
- Sprawl in the app chrome: 32 radius declarations, 28 font sizes, 11 durations, 7 easings, ad hoc em spacing. Only colour and the editor are tokenised.
- Shortcut group titles: text at 50%, 2.58:1.
- Markdown markers `#d9d9d9` are 1.41:1. That is fine as ornament, but in a Markdown editor the markers are content the writer edits.
- Editor H1 is 2x the body (30px over 15px), under a 3x display-jump rule. For a writing tool this may be a register choice; flag it, don't copy it blindly.
