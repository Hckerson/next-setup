# Pipeline

How assets are made offline: Blender run headless from scripts, then optimised and verified for the browser. Written 2026-11-12 before Blender was installed; every script below is planned, and each is marked tested only after it has produced an asset that passed its check.

## The machine

Measured 2026-11-12: Intel Core i7-8569U (4 cores, 8 threads), Intel Iris Plus Graphics 655 (Metal 3). Cycles renders on the CPU here; EEVEE uses the GPU. Plan for minutes per baked map and minutes per offline frame; measure the first of each and record it below before promising a sequence. `ffmpeg` is not installed: encode video in the user's Chrome through WebCodecs (`techniques.md`, Media) or install a static `ffmpeg` with the owner's approval.

## Running Blender

```
BLENDER=${BLENDER_PATH:-/Applications/Blender.app/Contents/MacOS/Blender}
$BLENDER --version
$BLENDER --background --factory-startup --python .claude/skills/stagecraft/tools/blender/<script>.py -- <args>
```

Everything after `--` reaches the script as its own arguments. Scripts read a JSON spec, never values typed into the script, so one script serves every build. Outputs go to `public/stage/<feature>/` and are recorded in that folder's `manifest.json` with source "Blender (generated)" and the spec that produced them.

## Into the browser

- **Optimise:** `pnpm exec gltf-transform optimize in.glb out.glb --compress meshopt --texture-compress webp` (KTX2 needs KTX-Software; without it use WebP and say so).
- **Lightmaps:** read on UV1 by the material; the moving actors take real-time light that matches the baked sun.
- **Vertex animation:** a loader in `lib/stage/` reads the textures and bounds; a TSL node samples the frame from the timeline's progress, so the scroll scrubs the simulation exactly in both directions. Written alongside the first baked output, tested against Blender's frames.
- **Sequences:** encoded for seeking (`techniques.md`, Route B), scrubbed by mediabunny on the phone tier.

## Baked light for any static set

`tools/blender/bake_set.py` takes a set spec (JSON, y-up, metres) and returns a GLB of the static set plus one lightmap per baked object, holding Cycles' soft shadows, bounce and caustics. Object types: `box`, `plane`, `lathe` (a profile turned about y), `glb` (any model), and `window` (an invisible wall with an opening and mullions, aimed along the sun, that only shapes the light). Materials are PBR with texture maps; `tileMetres` sets how many metres one square texture tile covers; a texture that is not square takes `repeat` instead (tiles per metre along the two world axes, before rotation; a 1 × 0.5 m texture is `[1, 2]`), and `uvRotation` turns it in degrees, so boards can run the length of a table. Texture coordinates are projected in world metres so texel density is the same on every object. Lights: a `sun` with a direction, a colour temperature, a strength and an angular size (the size is what softens shadows with distance). An HDRI environment. `caustics: "caster"` on glass and `"receiver"` on surfaces turns on Cycles' shadow caustics. `bake: true` and `bakeSize` per object.

On the web, `BakedSet` (`components/wrappers/baked-set.tsx`) loads the GLB and applies each lightmap on the second UV set; moving actors keep real-time light, and `ShadowCatcher` lays their real-time shadows over the baked surface. Static objects already in the bake must not also cast real-time shadows, or the shadow doubles.

Units, measured 2026-11-13:

- **The bake's sun strength and environment strength equal the real-time ones**, in the same physical units (a three directional light's intensity and a Blender sun's strength are both irradiance). Read them from the stage constants, never retype them.
- **`lightMapIntensity` is π.** Blender's diffuse bake (direct and indirect, colour off) stores irradiance divided by π; three divides a lightmap by π again. At 1 the set renders about three times too dark.
- **The first shot plays itself; scroll takes over.** A page that opens at film time 0 opens on an empty set, and the hero only appears once the visitor scrolls. `useStageTimeline` takes an `opening` (the film time where the first shot's last move ends, derived from the script, never typed) and a `ready` flag from the scene's mount: until ready, a poster (the real render at time 0, `/lookdev?at=0`, recorded in the manifest) sits under the canvas; once ready, the film plays to the opening on its own and scroll scrubs the rest. A reload mid-page skips it; reduced motion holds the peak. Finish the first shot's moves before its copy fades, or the opening lands on an empty column (Receipt: print ends at 55 percent of the shot, leaving a hold). An `opening` of duration 0 skips the draw-on and opens straight on that frame, with the poster rendered at the same time: the blind critic graded a poster at film time 0 (an empty sheet) SET-G4-5 as the first paint, so Receipt opens on the printed receipt, 2026-11-16.
- **A baked set suspends until its lightmaps load.** `BakedSet` loads every lightmap with `useLoader`, so no mesh paints with its raw GLB material. Loaded asynchronously, the pad painted for a frame in its original material lit by the environment probe; with a blue sky probe, a cold first load showed a slate-blue sheet (critic round 11 graded it SET-G4-4, measured b/r 1.31 against 0.88), 2026-11-16.
- **A window bar must cast along the sun.** On the floor a vertical mullion's shadow runs along the sun's azimuth, the same way objects cast; a horizontal bar's runs across it. Viewers read a stripe as the beam's direction, so a horizontal bar crossing the hero reads as a second light (critic round 9 on Receipt: LGT-G4-5). Choose `panes` so the bar that crosses the actor is vertical (Receipt: `[2, 1]` puts one through the aim point) and check that its stripe and the actor's cast shadow share an axis.
- **Shade needs a sky.** A set lit by a sun and an interior HDRI has neutral or warm shade, because bounce from wood and kraft warms it, and no grade can turn that cool without tinting the lit side too. Give the environment `"sky": true` and `bake_set.py` builds Blender's Nishita sky without a sun disc, aimed from the first sun key, so skylight and sun agree. Match its `strength` to the irradiance it replaces so exposure holds: on Receipt the office HDRI's upper hemisphere measured 0.906 luminance at strength 0.6 and the sky 4.30 at strength 1, so 0.126. Shaded paper's blue-to-red ratio went from 0.865 (lit 0.869) to 0.961 (lit 0.912), measured 2026-11-15.
- **Every lightmap is denoised.** `bake_set.py` runs Blender's Open Image Denoise over each lightmap after it is baked (`"bake": { "denoise": false }` turns it off). Undenoised bounce at 96 samples showed on the stage as a crosshatch in the shade, which a viewer reads as a texture; denoised, texel-to-texel noise fell from 0.62 to 0.03 on a plaster wall and from 0.67 to 0.22 on dark planks, and mean light moved by about a tenth (measured 2026-11-13). Denoise first, then add samples only if the critic still sees grain.
- **Lightmap resolution follows the detail you need.** At 512 px a 3.2 m desk gets 6 mm per texel and blurs the caustic; 2048 px gives 1.6 mm. Measured on this machine: 512 px at 64 samples, 24 s; 2048 px at 128 samples, 4 min 48 s.
- **Clear glass blocks direct light in a plain bake.** Cycles leaves the table under a glass jar black, which reads through the glass base as a black slab. Give glass `"shadow": "transparent"` (and a `shadowTint`): shadow rays pass through as a tinted transparent surface and the glass casts the pale shadow real glass does. It costs the Cycles caustic through that object (measured 2026-11-13); a caustic then needs its own light source in the bake or a projected texture.
- **Caustics have their own layer.** A plane in the set spec with `"caustic": { "caster": "<glass object>" }` (and `"materialFrom": "<the surface it lies on>"`) bakes only the light the glass focuses: the sun alone (the sky off), one diffuse bounce, every object hidden but the catcher, the glass and the window, baked once with the glass and once without, the difference kept and a 3 × 3 median applied. The stage adds it over the surface (`userData.additive`), so the caustic shows where the surface is in shadow, as a real one does. Measured 2026-11-13 with Cycles' shadow caustics (MNEE): a sun works (a glass sphere focuses the floor to 2.14 against 1.59 open), and a solid glass cylinder throws bands as bright as direct sun (256 px at 256 samples, 9 s).
- **An empty glass barely focuses.** MNEE found no caustic through an empty jar's two thin walls, and a real empty glass throws a pale shadow with bright lines at its edges, not a focus. A strong caustic needs a solid or filled body: a glass block, a bottle of liquid, a lens, a jar of water. For an empty vessel, the pale tinted shadow (`"shadow": "transparent"`) is the honest result; ask whether the concept wants it filled.
- **Reflector cards make metal read as its colour.** A metal shows what it reflects, and in a real room most of what faces a coin is dim: gold went olive and black in shade and cream in the sun (a blind critic graded it Fourth). Product photographers fix this with cards out of frame. `"type": "card"` (size, position, aim, color, strength) is an emissive plane that appears only in reflection probes: hidden from lightmap bakes unless `"lights": true`, never exported, casting no shadow. An overhead warm card at strength 2 (a white card in sun is about 1.5) and a smaller one behind the hero took the coins from darker than the set (0.66) to brighter (1.7) and their highlights from pale (0.20) to gold (0.39), with no change to the lightmaps.
- **Re-export without baking.** `-- <set.json> <out> export` rebuilds the GLB (materials, textures, geometry) and points it at the lightmaps already in `<out>`, in seconds. Use it for a texture or material change that does not move light; the bounce colour in the old lightmaps is then slightly stale. Measured: 6 s against a 22 min bake. The bounce-and-sky bake costs twice a full bake, because it subtracts a sun-only bake.
- **Reflection probes.** `"probes": [{ "name", "position", "size", "samples" }]` renders an equirectangular HDR (`<name>_probe.hdr`) from each point with Cycles, denoised, after the lightmaps; `-- <set.json> <out> probes` renders only the probes. Place a probe where the reflective actors stand; three reads it with the same orientation (checked: the back wall lands at −Z). The window object is invisible to the probe as it is to the stage, so through it the probe sees the HDRI. Measured: 512 × 256 at 16 samples, 13 s.
- **Nothing baked may also receive real-time shadow.** Give `ShadowCatcher` a hole (`holes`) over every footprint the bake already holds, or the two shadows stack.
- **A blind critic reads the light, not the rig.** In one review a window's shadow edge was read as an opaque glass shadow. When light is technically right and still misread, the composition is wrong: move the patch, the object or the camera until the light reads at a glance.
- **One source for the sun and the window.** The set spec names the hour once, in `keys` (written by `tools/sun-keys.mjs`, even for a single still sun). The bake takes the sun's direction and colour, and the window's facing, from the first key. The stage parses the same file with `setSpecSchema` (`lib/validations/set-spec.ts`) and reads its hour, sun strength and window from it (`windowOf`), so the baked and real-time light cannot drift apart.
- **A moving sun is baked in keys.** `tools/sun-keys.mjs <set.json> <hour> [hour...]` writes a `keys` list into the set spec, each with the sun's direction and colour from `lib/stage/sun.ts`, so the bake and the real-time sun can never disagree. `bake_set.py` unwraps each object once and bakes one lightmap per key (`<object>_lightmap_<key>.hdr`); the GLB lists them in order as `userData.lightmaps`. On the web, `BakedSet` takes a `sunKey` uniform and blends neighbouring keys; `keyAt(hours, hour)` in `lib/stage/sun.ts` turns the story's hour into that key, so the timeline drives the light.
- **Blend only soft light.** Cross-fading two keys that hold a sharp window shadow shows both shadows at once halfway. For a sun that moves while the camera watches the shadow, bake with `"bake": { "passes": "indirect" }`: the lightmaps hold everything but the sun's direct light (the full bake minus a sun-only direct bake, so sky light and every bounce stay; an earlier version dropped all direct light, and shade went black because the sky's direct light was lost), the set takes the real-time sun (`BakedSet`'s `direct` lights only, never the fills, which would count the bounce twice, and never the HDRI, which the bake already holds), and the window casts real-time shadow (`WindowSun` without `baked`). Full passes suit a sun that holds still or moves off camera. Measured on Sunline (three keys, 15:00 to 17:00, 512 px, 96 samples, 26 s): the pool of sun slides across the desk and up the wall as the hour changes, and an hour between keys blends with no double shadow, because the blended maps hold only soft light. A dark set returns little bounce, so its shade in a bounce bake is darker than in a full bake; meter exposure per hour or lift the sky.

## Rigid bodies: Bullet in Blender

`tools/blender/bake_rigid.py` bakes pours, falls and scatters with Blender's Bullet from a JSON spec: gravity, substeps and solver iterations, a ground, a container (a cup, a box or any GLB), the body (cylinder, box or any GLB), a drop (count, origin, spread, interval, velocity, spin, seed, window, clearance) and a settle phase. It writes `<name>.json` and `<name>.bin` in the format `lib/stage/baked-rigid.ts` plays; the same spec always gives the same bytes.

The Node bake on Rapier was removed on 2026-11-14. Measured 2026-11-13 with `tools/overlap.mjs` and Rapier's own contact query, Rapier (0.21 and 0.19.3) cannot hold a pour of thin discs: a coin dropped flat on a coin settles 1 mm into it, and a pour of 30 ends with hundreds of interpenetrating pairs (worst 7 to 19 mm) whatever the collider, stiffness, substeps or CCD. Bullet gives zero on the same pour. Do not bring it back for thin bodies.

Three rules make Bullet stable:

- **Simulate ten times larger** (`blenderScale`, default 10) with gravity scaled to match: the motion is identical in time, and Bullet's margins become negligible at coin scale.
- **A vertical conveyor, never a teleport.** Each body waits as a kinematic object descending straight down onto its spawn point at the pour speed, and is released there. A kinematic body that jumps (teleports) carries an enormous velocity for one step and throws its neighbours at hundreds of metres per second (measured). A slanted path lets a waiting body clip a falling one.
- **Spawn points clear of each other.** Bodies released within `drop.window` frames of each other spawn at least one body-width (`drop.clearance`) apart horizontally, at one height, so their vertical paths never cross.

**A pile must end still.** Large piles of thin bodies never sleep on their own: numerical jitter keeps them creeping a fraction of a millimetre. A `settle` phase after the last body lands (`"settle": { "from": <frame>, "linear": 4, "angular": 8 }`) raises damping so the residual energy drains; it changes nothing visible because the pile has landed. Deep piles still twitch, so add `"freeze": { "after": <frame>, "window": <frames> }` inside `settle`: the calmest frame in the window is held to the end. `node tools/freeze.mjs <bake.json> <after> <window>` does the same to an existing bake. Measured: 360 coins frozen at frame 816, zero overlaps.

Run it: `/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python .claude/skills/stagecraft/tools/blender/bake_rigid.py -- <spec.json> <out-dir>`, then always check the result with `discOverlap` from `tools/overlap.mjs`. Budget the time: bake time grows faster than the body count.

## CC0 sources

`tools/assets.mjs` fetches HDRIs and texture sets from Poly Haven (CC0) with their real-world dimensions, so materials are scaled correctly. ambientCG is the second CC0 source; add it to the tool when a build needs it.
