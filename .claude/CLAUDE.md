# Project Instructions

Reusable **Next.js App Router starter**: architecture and conventions, one example per non-UI layer. UI layers start empty.

## Rules

1. **No hardcoding.** Routes, durations, enums and copy used twice go in `lib/constants.ts` (or `lib/<feature>/constants.ts`). Seed data goes in `lib/data/`, never inline in a page.
2. **Single source of truth.** Name a recurring decision once as a token and reference it.
3. **Match the existing architecture.** Don't invent patterns or locations; state the reason before deviating.
4. **Minimize LOC.**
5. **No `console.*` or debug statements.** Logging belongs in services.
6. **Never delete a feature because it is not built.** Stubbed, scaffolded and unused exports, routes, schemas, types, enums, rules and codemods are work in progress. Removal needs an explicit instruction naming the feature; if something looks dead, say so and wait. Same for design OS artifacts (`design-os/MASTER_PROMPT_COMPLETE.md` › Scope Preservation).

## Patterns

- **Styling:** Tailwind utilities on the tokens in `styles/tokens.css`. Promote to a named class in `globals.css` only when a pattern repeats.
- **Components:** reuse `components/ui` and `components/common` first. A pattern used twice leaves the page that birthed it.
- **Pages:** `page.tsx` composes sections and holds page-level state only.
- **Types:** shared domain types live in `lib/types/<domain>.ts`, re-exported from `lib/types/index.ts`.
- **State:** TanStack Query for server state; local state, URL params, or `useSyncExternalStore` + `localStorage` otherwise. A global store needs a stated reason.
- **Validation:** Zod in `lib/validations/`, types via `z.infer`.
- **IDs:** `nanoid`, never `uuid` or `Date.now()`.
- **Async:** components use hooks in `lib/hooks/use-<resource>.ts`, never the client directly. Authenticated mutations wrap a Server Action from `lib/actions/`; authenticated reads use a Server Component or GET route handler, never a Server Action (they run serially and are never cached).

## Layout

Component layers under `components/`: `ui` (domain-free primitives), `common` (shared compositions), `wrappers` (motion, boundaries), `brand`, `patterns` (domain-free compositions), `features` (domain marks, rows, modals), `sections`, `layout` (chrome), `providers`. See `docs/UI_LAYERS.md`.

UI quality: the `web-generations` skill holds every layer to the fifth generation, in the register named in `docs/DESIGN_BRIEF.md`.

`lib/` has no JSX. The cinematic stage runs on libraries (gsap, lenis, three on WebGPU via @react-three/fiber); the cinematic-web skill owns how. `tools/` is not app code.

New ESLint rules go in `tools/eslint/rules/` with a colocated `.test.ts`, registered in `eslint.config.ts`; use plain flat config where it suffices. A rule whose fix spans files gets a codemod in `tools/codemods/` (dry-run by default, `--write` to apply, skip and report when intent would be guessed).

## Contract layer

`lib/contract/` is generated by `pnpm contract` from the backend's OpenAPI. Never edit it. Import request shapes and endpoints from `@/lib/contract`; `lib/api-routes.ts` is only for endpoints the backend doesn't publish. Hand-written Zod composes over generated schemas (`.extend`, `.pick`). A response type reaches the contract only if the controller method has `@ApiEnvelope(Dto)` in `nest-setup`; otherwise the endpoint is `Endpoint<unknown>`.

## Files

- One component per file, kebab-case name matching the export. Exception: compound primitives in `components/ui/` (`Menu` + `MenuContent`).
- Absolute `@/` imports only.
- Split files over ~150 lines.

## Before commit

No git hooks run. Gate manually: `pnpm type-check`, `pnpm lint`, `pnpm contract:check`.
